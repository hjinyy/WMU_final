# File responsibility and data flow

The repository has a one-way reproduction flow:

`data/frozen_inputs + data/reference` → `src/wmu_final` → `scripts/render|audit` → `outputs` → `tests`

- **Frozen input tables** are not generated by these scripts. `data/frozen_inputs/predictions` and `metrics` hold only previously computed rows required by the selected paper figures. `waveforms_selected` contains six channel-reduced archived traces for matched SSO comparisons. The full raw corpus and simulation models are outside this repository.
- **Reusable source** is limited to network branch lists used for schematic layout and functions to load the frozen feature tables and calculate normalized spatial features. It contains no orchestration, rendering entry points, or model-training pipeline.
- **Scripts** are executable entry points. `scripts/render` owns plot creation; `scripts/audit` owns the pre-fault persistence audit. Each script writes to one explicit child of `outputs` and refuses overwrite unless `--force` is supplied.
- **Outputs** are deliverables, not inputs to the generators. Image/PDF, caption, numerical plot data, metadata, and diagnostics remain together under each named deliverable.
- **Tests** check role boundaries, expected output inventory, provenance, and frozen-input hashes. The package inventory is SHA-256 based and stored with the provenance files.

Do not put archived prediction tables under `outputs`, and do not put rendered figures under `data`: those locations indicate different provenance and lifecycle.
